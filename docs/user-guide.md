# KooEval 功能使用说明

KooEval 用于把真实业务中对 Agent 的人工测试，沉淀为可复查的评测记录、截图证据与 Badcase 闭环。它不直接调用 Agent：评测人员先在真实业务系统中与 Agent 交互，再将必要的输入、回答、截图和判断记录到 KooEval。

## 1. 谁可以使用哪些功能

| 角色 | 适用人员 | 主要权限 |
| --- | --- | --- |
| 成员 | 日常评测人员、研发协作者 | 查看评测资料，创建与完成评测，填写评分和证据，登记及跟进 Badcase，查看结果与看板。 |
| 运营管理员 | 负责评测运营的人员 | 包含成员能力；还可维护评测配置、评测集及版本、用例标签、问题标签和审计日志。不能管理用户。 |
| 超级管理员 | 少量系统责任人 | 拥有全部菜单和运营管理员能力；可创建、编辑、启停用户并重置用户密码。 |

新建用户的初始密码为 `123456`。该用户第一次登录后必须完成改密，之后才能进入系统；超级管理员重置密码后也会重新触发此流程。

## 2. 推荐工作流

```text
运营管理员配置评测对象与场景
        ↓
创建评测集 → 录入或导入用例 → 发布版本
        ↓
成员创建评测并在真实业务系统中执行
        ↓
填写评分、可选回答与截图；必要时标记 Badcase
        ↓
在 Badcase 中心分派、处理、复核和关闭
        ↓
通过首页、看板和导出复盘质量变化
```

场景用于归类和筛选，不应阻塞用例导入。评测集归属于一个评测对象，同一评测集可包含该对象下不同场景的用例；用例可以在后续逐步补充场景。

## 3. 开始前：评测配置（运营管理员）

进入“系统管理 → 评测配置”，先建立团队共用的基础信息：

- **评测对象**：被评测的 Agent、应用或能力边界。停用对象后，不能再用于新的评测或新数据录入；历史记录仍保留可追溯性。
- **评测场景**：对象下常见的业务场景，用于查看覆盖面和筛选。场景不是用例创建的强制前置条件。
- **用例标签**：用于给评测用例分组、检索和统计。标签可以是全局可复用标签，也可以只对某个评测对象生效。
- **问题标签**：用于标注 Badcase 的问题类型，例如事实错误、拒答、格式问题或安全边界问题。它与用例标签不同，服务于问题统计和后续处理。

建议先创建最少但稳定的一组对象、场景和标签；避免用相近名称重复建项。对象、场景或标签停用前，请先确认不会影响仍在进行的工作。

## 4. 管理评测集与用例（运营管理员）

### 4.1 创建评测集

在“评测集”中选择评测对象并创建评测集。评测集是用例的容器，而不是单一场景的容器；它可以覆盖对象下多个场景。

评测集通过版本管理用例：

- 草稿版本可以继续新增、编辑、导入或删除用例。
- 发布后版本保持不可变，已创建的评测继续指向当时的版本，因此结果可复查。
- 需要调整内容时，基于评测集新建草稿版本，再编辑并发布。

### 4.2 新增或导入用例

用例最重要的是用户输入。用例名称不是必填项，系统会以输入摘要帮助识别用例；场景也可以暂不填写，后续再补充归类。

可在评测集草稿中：

- 在用例列表底部展开编辑区，快速新增或编辑用例。
- 单条录入用户输入、可选名称、评判要点、标签和场景。
- 下载 CSV 模板后批量导入；先检查预览，再确认写入草稿。
- 发布前检查必填输入、标签与场景的合理性。

评测集详情可查看任意历史版本的内容；列表页只展示有限用例预览，查看更多进入详情页。

## 5. 开展评测（成员、运营管理员、超级管理员）

在“我的评测”中按评测对象和已发布的评测集版本创建评测。随后进入评测工作台，按用例顺序进行人工判断：

1. 在真实业务系统中输入该用例，观察 Agent 表现。
2. 在工作台选择评分。评分是完成一条评测的必要信息。
3. 需要留证时，粘贴或上传现场截图；也可按需填写 Agent 回答。二者均为可选项。
4. 如果发现质量问题，标记为 Badcase，填写问题说明并可选择问题标签。
5. 完成全部用例后提交完成；无法评测的用例可跳过并说明原因。

低分（1～2 分）会自动打开 Badcase 标记，便于及时登记。是否记录回答和截图应以能否支持后续复核与定位为准：满意结果可只记录评分；问题结果建议至少保留关键截图或说明。

评测工作台会显示总用例、待评、已评、跳过与进度。可中途退出，之后从“我的评测”继续；完成后的评测记录仍可查看，必要时按权限重新打开处理。

## 6. 主动登记 Badcase

不是所有问题都来自正式评测。发现真实业务问题时，进入“Badcase 中心 → 主动登记 Badcase”：

1. 选择评测对象；没有可用场景的对象不能开始登记。
2. 填写原始输入、问题描述，可补充背景回答和现场截图。
3. 选择场景、问题标签，并补充运行环境、Agent 版本、发生时间等定位信息。
4. 提交后可继续登记下一条，系统会保留对象、场景、环境和 Agent 版本等上下文，清空本条问题内容。

截图支持粘贴、拖拽或文件选择，可排序和删除；支持 PNG、JPEG、WebP，默认单张不超过 10 MB、每条最多 10 张。登记页面会保存文字草稿和选择项，不保存截图，因此恢复草稿后需要重新选择截图。

Badcase 列表支持按评测对象、场景、状态、负责人、问题标签和时间筛选。列表中的“评测对象”说明问题归属；场景筛选位于“更多筛选”。

## 7. 跟进 Badcase

打开 Badcase 详情可查看来源、原始输入、评测或业务证据、附件、问题标签与活动时间线。团队可根据权限进行：

- 指派或取消负责人。
- 开始处理、延期、解决、重新打开或无效化问题。
- 追加处理备注，保留过程与责任记录。
- 通过问题标签统计高频问题类型。

状态更新前应确认问题是否已验证；不要用“已解决”代替“暂未处理”。对重复问题，建议通过标签、负责人和备注关联处理上下文，避免重复创建无效记录。

## 8. 查看结果与复盘

- **首页**：查看个人待办、近期评测和需要关注的 Badcase。
- **数据看板**：按对象、场景、评测集版本、时间等维度查看完成情况、评分和 Badcase 分布，并可钻取到明细。
- **评测结果**：集中检索已完成的评测记录，查看用例级评分、回答、附件和 Badcase 标记。
- **全局搜索**：快速定位对象、场景、用例、回答或 Badcase。
- **CSV 导出**：导出评测结果、Badcase 列表或 Badcase 分布，用于离线复盘。导出的截图地址仍需要登录权限。

复盘时建议同时看评分分布、Badcase 数量与问题标签，而不是只看平均分。对于评分下降或 Badcase 集中的场景，再回到具体版本、用例和截图证据定位原因。

## 9. 用户与审计（管理员）

“系统管理 → 用户管理”仅对超级管理员开放，用于维护用户名、显示名称、邮箱和角色。建议至少保留两名可用超级管理员，避免单人不可用导致无法管理系统。

“审计日志”对运营管理员和超级管理员开放，记录关键的配置、用户与业务操作；带有用户主体的日志会保留用户名，便于追溯操作来源。常规成员无需通过审计日志开展日常评测。

## 10. 使用建议

- 先稳定评测对象和基础标签，再逐步扩展场景覆盖；不要因场景尚未完善而延迟导入用例。
- 用例输入要保持可复现，评判要点写清楚“什么表现算通过或有问题”。
- Badcase 的原始输入和问题描述应能让未参与现场的人理解问题；对复杂问题优先补充截图、版本和环境。
- 每次发布评测集版本后，记录其用途和变化范围，便于比较不同版本的评测结果。
- 定期清理重复、过时的标签和场景，但不要删除已用于历史记录的事实数据；优先停用并保留追溯链路。
