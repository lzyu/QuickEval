# QuickEval V1 前端页面与关键交互设计

> 状态：设计基线已确认
>
> 技术栈：Vue 3 + TypeScript + Vite + Element Plus
>
> 视觉参考：[`page_refer`](../page_refer)
>
> 更新日期：2026-07-26

## 1. 设计目标

QuickEval V1 面向小团队内部使用，前端优先保证评测录入高效、证据完整、状态清晰和历史结果可追溯。页面不引入任务分配、审批、多租户和复杂角色配置。

设计原则：

- 常用工作从首页最多两次点击进入。
- 评测工作台优先服务桌面端连续录入，不为移动端重新设计完整工作流。
- 生命周期操作使用明确按钮和确认对话框，不允许直接编辑状态字段。
- 已发布版本和已完成评测默认只读，避免误改历史快照。
- 列表筛选进入 URL 查询参数，刷新和分享链接后保持当前视图。
- 前端负责及时反馈，所有权限、状态和数据约束仍由服务端最终校验。

## 2. 信息架构

### 2.1 一级导航

| 导航     | 面向用户 | 主要内容                             |
| -------- | -------- | ------------------------------------ |
| 首页     | 全部用户 | 个人待办、最近评测集和近期活动       |
| 评测集   | 全部用户 | 浏览评测集与版本；管理员维护内容     |
| 我的评测 | 全部用户 | 当前用户的进行中、已完成和已作废评测 |
| Badcase  | 全部用户 | 查询、登记、定位和闭环处理 Badcase   |
| 数据看板 | 全部用户 | 评测质量与 Badcase 分布              |
| 系统管理 | 仅管理员 | 基础配置、用户、问题标签和审计日志   |

“系统管理”只包含：

- 基础配置：评测对象、场景、全局用例标签和对象专属用例标签。
- 用户管理。
- 问题标签管理。
- 审计日志。

V1 不显示“角色管理”“权限管理”和通用“系统设置”。角色固定为普通成员、管理员两种。

## 3. 全局页面框架

### 3.1 应用外壳

- 左侧固定导航栏，展开宽度约 208～220 px，支持折叠。
- 顶部栏固定，包含面包屑或当前模块、全局搜索入口、帮助入口和用户菜单。
- 内容区使用浅灰背景与白色卡片，主操作色为蓝色。
- 内容区最大宽度不强制锁死；表格和工作台应充分使用大屏宽度。
- 桌面端最低支持宽度为 1280 px；低于该宽度时允许横向滚动，不压缩评测证据区域。

用户菜单包含个人信息、修改密码和退出登录。管理员身份只通过角色名称或徽标提示，不另设一套应用外壳。

### 3.2 状态展示规范

评测集版本：

- 草稿：灰色。
- 已发布：绿色或蓝绿色。
- 已归档：中性灰色。

评测记录：

- 进行中：蓝色。
- 已完成：绿色。
- 已作废：灰色并带删除线或明确“已作废”徽标。

Badcase：

- 待处理：灰色。
- 处理中：橙色。
- 已解决：绿色。
- 暂不处理：紫色或中性棕色。
- 已无效：红色描边或浅红底，并与业务状态分开展示。

代码和页面文案必须统一使用“待处理、处理中、已解决、暂不处理”，不使用“待复核”“已指派”等额外状态。

### 3.3 通用列表行为

- 筛选栏默认展示最常用条件，次要条件放入“更多筛选”。
- 筛选值、页码、每页数量和排序写入 URL 查询参数。
- 修改筛选条件后回到第一页。
- 支持“重置筛选”，恢复默认排序和分页。
- 表格首次加载显示骨架屏；翻页时保留表头并显示局部加载状态。
- 空数据区分“系统暂无数据”和“当前筛选无结果”。
- 行操作超过两个时使用“更多”菜单；危险操作与常用操作不相邻。
- 成功写操作用短消息反馈，关键状态变更同时刷新当前资源和相关统计。

### 3.4 全局搜索

顶部搜索支持场景、评测集、用例和 Badcase。输入停顿后请求搜索建议，按类型分组展示；选择后跳转到对应详情页。搜索只用于快速定位，复杂查询仍在各模块筛选栏完成。

### 3.5 权限与路由守卫

SPA 启动时先调用 `GET /api/v1/auth/session`：

- 未登录访问业务路由时跳转 `/login`，登录成功后返回原地址。
- 使用初始密码登录的用户会被直接引导到设置新密码页；改密完成前不能访问其他页面。
- 普通成员访问 `/admin/*` 时显示 403 页面，不通过隐藏菜单替代服务端鉴权。
- Session 失效时清理用户状态，保留当前地址并跳转登录。
- CSRF Token 只保存在内存中的认证 Store，并自动附加到非安全请求。
- 页面按钮根据服务端返回的 `permissions` 和资源 `allowed_actions` 控制，不在前端复制完整状态机。

## 4. 页面设计

### 4.1 登录页

- 支持用户名或邮箱加密码登录。
- 提交期间禁用按钮，防止重复登录。
- 登录失败只显示统一提示，不暴露账号是否存在。
- 连续失败触发限流时展示服务端提示和可重试时间。
- V1 不显示注册、找回密码和 OA 登录按钮；后续通过 `oa_login_enabled` 功能开关扩展。
- 新建账号的初始密码固定为 `123456`；首次登录必须设置新密码。已登录用户仍可从个人菜单主动修改密码。

### 4.2 首页

首页由 `GET /api/v1/pages/home` 一次加载：

- 顶部概览卡：我的进行中评测、我的已完成评测、分配给我的未关闭 Badcase。
- “继续评测”：按最近编辑时间展示进行中的评测。
- “待处理 Badcase”：展示分配给当前用户的待处理和处理中记录。
- “最近评测集”：展示最近发布且可开始评测的版本。
- “近期活动”：展示与当前用户相关的必要动态。

卡片点击跳转到带预设筛选的目标列表。首页不承担全局管理看板功能。

### 4.3 评测集总览

普通成员可以浏览启用的对象、场景、评测集及已发布版本；管理员额外看到创建和维护操作。

主要交互：

- 按评测对象、场景、状态和关键词筛选。对象和场景使用级联选择：未选对象时不展开任何场景，选定后只提供该对象下的场景。
- 默认只展示启用评测对象下的评测集；管理员可通过“包含停用归属”查看历史评测集。
- 列表行可按需展开预览最新已发布版本的前 8 条用例；不预加载所有评测集的用例。超过 8 条时，通过“查看全部用例”进入详情页。
- 点击卡片或表格行进入评测集详情。
- “开始评测”默认选择最新已发布版本，也允许在详情页选择历史已发布版本。
- 管理员创建评测集时只选择启用的评测对象，并在同一事务中生成首个草稿。
- 已归档评测集默认隐藏，可通过筛选查看。

### 4.4 评测集详情与版本记录

页面包含基本信息、只读用例内容浏览器、版本时间线或版本表格和版本对比入口。用例内容浏览器默认展示最新已发布版本，可切换到其他已发布、已归档或草稿版本，并直接查看用例输入、场景归类、标签和启停状态。详情页按页加载用例，切换版本后回到第一页。查看已发布内容不需要创建草稿。

版本操作：

- 草稿：编辑用例、删除空草稿、发布。
- 已发布：开始评测、导出 CSV、复制为新草稿、归档。
- 已归档：查看、导出 CSV，不允许开始新评测。

如果评测集已有草稿，再次点击“创建草稿”应直接进入现有草稿，不创建第二份。
列表中“查看详情”始终进入只读详情；“编辑草稿”仅作为编辑动作，不再承担查看评测集内容的职责。

### 4.5 草稿用例编辑器

编辑器只允许操作草稿版本，页面顶部固定展示评测集、版本号、未发布状态和用例数量。

用例列表支持：

- 按当前列表顺序展示连续序号（1、2、3……），不提供手动调整顺序。
- 新增入口位于列表末尾，点击后在当前卡片内向下展开横向编辑区，不使用抽屉。
- 新增时“用户输入”是唯一必填项并优先聚焦；用例名称可留空，列表使用用户输入摘要识别该用例，不生成虚假默认名称。
- 名称、场景、标签和补充评测信息采用渐进披露；“添加并继续”保留场景和标签，方便连续录入。
- 已有用例点击“编辑”后直接在当前行下方展开同结构的横向编辑区，不使用侧边抽屉；保存或取消后焦点返回该行。
- 编辑用例名称、用户问题、可选场景归类、前置条件、期望结果、评判要点、用例标签和启用状态。
- 用例可以保持“待归类”；场景不完整不影响保存、导入和发布。
- 期望结果始终是可选字段。
- 单条编辑先在前端校验，再提交服务端；保存成功后更新 `lock_version`。
- 存在未保存表单时，离开页面需要二次确认。

批量操作：

- 下载 UTF-8 CSV 模板。
- 导入 CSV 并进入预览。
- 导出当前草稿或版本用例。
- 发布前打开确认对话框。

### 4.6 CSV 导入预览

流程为“选择文件 → 上传校验 → 预览 → 确认写入”：

1. 只接受 `.csv`，明确提示使用 UTF-8 编码。
2. 预览表展示原始行号、解析字段和行级错误。
3. 有错误时禁止提交，支持只查看错误行和重新选择文件。
4. 预览 Token 过期或草稿在预览后发生变化时，要求重新预览。
5. 提交成功后关闭对话框，刷新用例列表并定位到新增区域。

V1 只追加导入，不提供覆盖选项。
导入时不选择场景，新增用例默认进入“待归类”，后续在草稿编辑器逐条归类。

### 4.7 发布版本确认

对话框展示版本名称、启用用例数、停用用例数和发布后的影响。用户必须明确确认：

- 发布后内容不可修改。
- 后续修改需要复制新草稿。
- 评测将绑定该版本快照。

空版本或没有启用用例时，前端直接禁用发布按钮，并展示原因。发布成功后跳转评测集详情。

### 4.8 开始评测抽屉

抽屉展示所选评测集和版本，只提交：

- Agent 版本。
- 运行环境：测试、预发布、生产、其他。
- 评测目的或备注，可选。
- 配置说明，可选。

确认后创建独立 EvaluationRun 并直接进入工作台。按钮提交使用新的 `Idempotency-Key`；网络重试复用同一个 Key。

### 4.9 我的评测

默认只展示当前用户评测，支持状态、评测集、场景、环境、Agent 版本和时间筛选。

行操作：

- 进行中：继续评测；满足删除条件时允许删除。
- 已完成：查看结果；允许填写原因后重开。
- 已作废：只读查看。

管理员查看其他人员评测应通过明确的评测人员筛选，不改变“我的评测”默认语义。

### 4.10 人工评测工作台

工作台采用两栏主从结构，避免录入区被三栏同时挤压：

- 左栏：用例目录、状态、评分和 Badcase 标记，可按待评、已评、跳过筛选。
- 右侧宽工作区：标题仅在左侧目录展示，右侧不重复；上方用一张紧凑摘要统一展示用户输入、场景归类、评判要点、期望结果和前置条件，下方按“快速评分、现场截图、可选 Agent 回答、Badcase 判断”的顺序录入结果。
- 顶部统计采用单行紧凑状态栏，数字与完成进度合并展示，不使用大尺寸指标卡。

关键规则：

- 每题使用明确的“保存并下一题”，不对回答文本做逐字自动保存。
- 切换用例、离开路由或关闭页面时，如果当前题有未保存修改，必须提示。
- 评分是保存为已评的唯一必填项；采用紧凑的五段式 1～5 分选择器，不允许手动输入或取消为未评分。
- 每段同时展示分值和简短含义，完整含义通过悬浮提示展示，并支持方向键操作。
- 截图和 Agent 回答均可选；满意且无需跟进时只选择评分即可保存。
- 评分控件按内容宽度展示，不横向撑满结果区；现场截图与可选 Agent 回答并列为一组补充证据，Badcase 判断独立置于其后。
- 截图支持文件选择、拖拽，以及使用系统截图快捷键后在页面直接粘贴。
- 1～2 分自动标记为 Badcase 并展开问题信息，低分状态下不可关闭；从自动低分标记切换到 3～5 分时自动撤销，人工标记的 Badcase 则继续保留。
- 3～5 分时可独立标记 Badcase；只有标记后才展开具体问题和可选问题标签。具体问题是唯一必填信息，同时作为评测结果的定位评语；列表标题由具体问题自动概括。
- Agent 回答直接使用与截图上传区等高对齐的可选输入框，不增加额外展开步骤。
- 跳过用例必须选择预置原因或填写其他原因；跳过后清除评分，但保留是否清除已有证据需要二次确认。
- 截图允许 PNG、JPG/JPEG、WebP，每条结果最多 10 张，单张最大 10 MB。
- 上传区显示进度、失败原因、缩略图、预览、重排和删除。
- 所有用例已评或跳过后才启用“完成评测”。

完成评测前显示汇总确认：已评、跳过、已评分、Badcase 数量和未处理项。存在待评项时提供“定位第一条待评用例”。

### 4.11 已完成评测结果页

整体沿用工作台两栏主从结构，但默认只读：

- 左栏可按分数、Badcase、跳过状态定位用例。
- 右侧工作区先展示版本快照中的用例内容，再展示回答、截图、评分、评语和关联 Badcase。
- 顶部展示完成时间、平均分、评分覆盖率、Badcase 数量和跳过数量。
- “重开评测”必须填写原因；成功后返回可编辑工作台。
- “作废评测”是低频操作，放在更多菜单并进行强确认。

### 4.12 Badcase 列表

筛选条件包括对象、场景、来源、状态、负责人、问题标签、环境、Agent 版本、时间和关键词。评测对象是一级筛选条件，选择对象后才显示其所属场景。

列表规则：

- 默认只显示有效 Badcase，默认按问题发生或创建时间倒序。
- 来源明确区分“评测发现”和“业务发现”。
- 无效记录只有在开启“包含无效”后出现，并使用独立视觉提示。
- 点击标题进入详情。
- “主动登记 Badcase”先打开评测对象选择弹层；弹层默认仅显示可登记对象，并以可滚动的紧凑列表支持按对象名称或说明检索。已停用对象通过明确开关查看但不可选择；启用对象即使尚无场景也可进入。
- 导出使用当前筛选条件；超过同步上限时展示服务端错误，不在浏览器生成大文件。

### 4.13 主动登记 Badcase 工作台

独立工作台按评测对象组织连续登记。直接访问登记路由时，如果没有有效的
`evaluation_target_id`，必须先选择对象。页头展示当前对象并支持切换；左侧录入原始输入、
问题描述、Agent 回答和截图，右侧录入可选场景归类、问题标签、环境、Agent 版本和发生时间。
业务单号和会话 ID 收入“更多定位信息”。

交互规则：

- 原始输入、环境和发生时间必填；问题描述为辅助字段，留空时系统从原始输入生成内部标题。问题标签仅用于统计，可稍后补充；场景归类、Agent 回答、截图和 Agent 版本不必填。Agent 版本默认填入当天的 `YYYYMMDD`。列表、搜索和详情标题优先展示原始输入摘要，历史记录则回退到原有标题。
- Agent 回答和截图同时为空时只做提交前软提醒，确认后仍可提交。
- 截图支持剪贴板粘贴、拖拽、文件选择、预览、删除和排序；最多 10 张、单张最大 10 MB。
- “登记并继续”保留对象、场景、环境和 Agent 版本，清空问题内容、标签、截图和业务定位字段，并刷新发生时间。
- 草稿按用户和对象保存在浏览器中，只保存文本与选择项；恢复时提示截图需重新选择。
- 切换对象或离开页面时，如果存在未提交内容，需要二次确认。
- 创建与附件上传使用各自独立且可重试复用的 `Idempotency-Key`。Badcase 创建成功但截图上传失败后锁定记录，只允许重试上传或放弃截图，不得再次创建记录。
- 页面底部展示当前会话最近登记的 5 条记录，并可进入详情页。数据来源仍为 `business`，列表继续显示“业务登记”。

### 4.14 Badcase 详情

详情页分为问题证据主区和处理侧栏：

- 问题信息：场景、标签、严重程度、描述和期望表现。
- 用户问题与 Agent 回答。
- 原始截图与补充定位截图。
- 评测来源时展示关联评测、版本、用例、评测人和评分。
- 处理信息：当前状态、负责人、处理说明和允许动作。
- 基本信息：来源、登记人和关键时间。
- 处理记录：不可变时间线和新增备注。

状态操作：

- 待处理可进入处理中，也可直接解决或暂不处理。
- 处理中可解决或暂不处理。
- 已解决、暂不处理可重新打开为待处理。
- 状态变化、无效化和重新激活必须填写说明。
- 负责人可以分配或取消分配，变化进入时间线。
- 无效 Badcase 整页只读，只保留“重新激活”。
- 页面不提供物理删除。

发生乐观锁冲突时，不覆盖用户输入。弹窗说明记录已变化，提供“复制我的输入”和“刷新查看最新内容”。

### 4.15 数据看板

看板使用 `GET /api/v1/pages/dashboard` 聚合加载，筛选包括对象、场景、评测集、版本、评测人员、Agent 版本、环境、Badcase 来源、状态、标签和时间。

展示内容：

- 已完成评测次数、已评用例数、平均分、Badcase 数量和占比。
- 1～5 分分布。
- Badcase 问题标签分布。
- Badcase 状态分布。
- 跳过原因分布。
- 同一评测集不同版本的结果对比。

图表要求：

- 图例、坐标和悬浮提示明确统计口径。
- 空样本不显示误导性的 0 分或 0% 趋势。
- 点击图表分段可跳转到带相同筛选的明细列表。
- 导出按钮导出当前筛选下的原始 CSV，不导出图片截图。

评分、跳过原因和版本对比跳转到 `/evaluation-results`，问题标签、Badcase 状态和
Badcase 指标跳转到 `/badcases`。钻取必须保留对象、场景、评测集、版本、评测人、
Agent 版本、环境和时间范围，并追加被点击分段的精确条件。

### 4.16 系统管理

#### 基础配置

在同一页面以标签页管理评测对象、场景、全局用例标签和对象专属用例标签，减少 V1 页面数量。均只允许启用、停用，不物理删除。

各标签页使用实体化的主操作，而非泛化的“新建目录项”：可新建评测对象、评测场景或用例标签。评测对象行可直接发起“新增场景”或“新增标签”，自动带入所属对象；场景列表也可按评测对象筛选。

- 评测对象：名称、描述、状态。
- 场景：所属对象、名称、描述、状态。
- 用例标签：作用域、所属评测对象、名称、排序、状态。全局标签对所有评测对象可用，对象专属标签
  只对所属评测对象可用；用例编辑器按“全局标签”和“对象专属标签”分组展示。

停用前展示影响说明；存在历史数据时不改变历史归属，也不级联修改子资源自身状态。
评测对象停用后，其下历史评测集仍可查看并展示停用提示，但不能新建或编辑草稿、
发布版本、开始新评测或登记业务 Badcase；已经开始的评测允许继续完成。重新启用
对象后，其下评测集自动恢复可用；场景状态只影响新的用例与 Badcase 归类。

#### 用户管理

- 创建账号、编辑姓名/邮箱/固定角色；新账号初始密码固定为 `123456`。
- 启用、停用和重置为初始密码；首次登录必须设置新密码，用户列表展示待设置状态。
- 不提供删除用户。
- 不允许管理员停用当前登录账号。
- OA 身份不显示本地重置密码操作，或按服务端错误给出明确提示。

#### 问题标签管理

- 创建、编辑、拖动排序、启用和停用全局问题标签。
- 停用标签保留在历史 Badcase 中，但不再出现在新建选择器。
- 不提供删除。

#### 审计日志

- 仅管理员只读访问。
- 支持按操作者、动作、资源类型、资源 ID 和时间筛选。
- 列表展示操作者用户名；资源为用户时展示用户主体用户名。
- 展示请求 ID，便于关联服务端日志。
- 审计详情以字段差异展示，密码、Session、磁盘路径等敏感内容永不出现。

## 5. 通用交互与异常处理

### 5.1 表单

- 必填标记、字数限制和帮助信息在输入前可见。
- 字段错误展示在对应字段下方；全局业务错误展示在表单顶部。
- 服务端使用字段路径返回错误，前端映射到嵌套表单项。
- 抽屉和对话框关闭前检查未保存内容。
- 只有请求成功后才关闭表单；失败时保留全部输入。

### 5.2 加载、空状态和失败

- 页面首次加载：骨架屏。
- 局部刷新：保留已有内容并显示局部加载。
- 空状态：说明原因并提供当前用户有权限执行的下一步。
- 403：显示无权限页面。
- 404：显示资源不存在或不可见。
- 409 状态冲突：说明冲突原因并引导刷新。
- 422：优先展示字段和业务规则错误。
- 500：展示请求 ID 和重试按钮，不显示内部异常。

### 5.3 乐观锁

所有可变资源在页面状态中保存 `lock_version`，提交时携带期望版本：

- 成功后必须以响应中的新版本替换本地版本。
- `LOCK_VERSION_CONFLICT` 不做静默重试。
- 纯列表状态切换冲突后刷新该行。
- 长表单冲突先保留用户输入，再让用户选择刷新或复制内容。

### 5.4 幂等与重复提交

需要幂等 Key 的交互在一次用户意图开始时生成 UUID，并在网络重试中复用：

- 开始评测。
- 登记业务 Badcase。
- 标记评测 Badcase。
- 提交 CSV 导入。
- 新增 Badcase 备注。

按钮请求期间禁用。用户明确取消并重新发起时才生成新 Key。

### 5.5 图片预览与上传

- 选择文件后先在浏览器校验数量、扩展名和大小，但以服务端内容校验为准。
- 单张最大 10 MB，每个所属记录最多 10 张。
- 支持多选、逐张进度、失败重试、缩略图、全屏预览和键盘切换。
- 删除图片需要确认；若删除会违反证据要求，展示服务端返回的原因。
- 前端只保存附件 ID 和鉴权 URL，不接触服务器相对路径。
- 图片组件应处理 401、404 和损坏图片占位状态。

## 6. 前端工程结构

```text
apps/web/src/
├── api/                  # OpenAPI 生成客户端及轻量封装
├── assets/
├── components/
│   ├── app/              # 应用外壳、导航、页面标题
│   ├── data/             # 表格、筛选栏、状态徽标、空状态
│   ├── evidence/         # 回答文本、截图上传和预览
│   └── forms/            # 通用确认框、字段组件
├── features/
│   ├── auth/
│   ├── catalog/
│   ├── datasets/
│   ├── evaluations/
│   ├── badcases/
│   ├── dashboard/
│   └── admin/
├── router/
├── stores/               # 只存认证、权限和全局 UI 状态
├── styles/
├── types/                # 生成类型之外的前端视图类型
└── views/                # 路由级薄组件
```

约束：

- API 返回数据不整体放入 Pinia；页面数据由 feature 内的查询逻辑管理。
- 路由级组件只负责布局和组合，业务交互放在对应 feature。
- 状态枚举、评分文案和环境选项集中定义，不在页面重复硬编码。
- OpenAPI 生成类型不得手工修改；必要的展示模型通过映射函数产生。
- 不在 V1 引入微前端、低代码表单引擎或重量级全局状态框架。

## 8. 响应式与可访问性

- 登录页适配常见平板宽度；核心管理页面以桌面端为主。
- 评测工作台保持左侧目录与右侧宽工作区；窄屏时目录、用例内容和结果录入依次切换为单栏。
- 所有图标按钮必须有文字提示或 `aria-label`。
- 表单项、评分星级、图片排序和对话框可以使用键盘操作。
- 不能只依赖颜色表达状态，同时展示文字或图标。
- 正文和交互文字满足企业后台的基本对比度要求。
- 焦点进入抽屉或对话框后限制在容器内，关闭后返回触发按钮。

## 9. 前端验收重点

- 普通成员无法进入管理员页面，但可以独立开始评测和登记 Badcase。
- 同一成员可对同一版本创建多次独立评测。
- 已发布版本不可编辑，已归档版本不能开始评测。
- 用例期望结果可为空。
- 评分只能选择 1～5 分，保存为已评时必须评分。
- 选择 1～2 分时自动标记 Badcase，并要求补全问题信息；升至 3～5 分时正确处理自动标记状态。
- 未提供回答文本或截图时仍可保存；两者都只作为可选证据。
- 截图支持选择、拖拽和粘贴上传。
- 未标记 Badcase 时不展示或要求填写评语；标记后必须补全问题信息。
- 跳过必须填写原因，且不进入平均分和 Badcase 比例。
- 所有用例处理完成前不能完成整次评测。
- 评测 Badcase 与业务 Badcase 正确展示各自来源上下文。
- Badcase 状态只出现待处理、处理中、已解决、暂不处理。
- 用户、标签和 Badcase 不提供物理删除入口。
- 图片单张 10 MB、每条最多 10 张，支持多图预览。
- 刷新列表页后保留筛选和分页。
- Session 失效、403、乐观锁冲突和上传失败不会丢失用户未提交输入。

## 10. 视觉稿使用说明

`page_refer` 中图片用于页面布局、层级、密度和视觉语言参考，不作为业务规则的最终来源。实现时以下规则优先于图片中的生成式文案：

- 截图单张上限为 10 MB，不是 5 MB。
- 用户只能启用或停用，不能删除。
- V1 没有角色管理、权限管理和复杂系统设置。
- Badcase 状态固定为待处理、处理中、已解决、暂不处理。
- `Badcase 详情页.png` 是详情页；主动登记使用 `评测对象选择弹层.png` 和 `主动登记 Badcase 工作台.png`，不再使用列表抽屉。

最终前端应复用同一套 QuickEval Logo、导航尺寸、颜色变量、圆角、阴影和表格密度，不逐页复制视觉稿中的偶然差异。
