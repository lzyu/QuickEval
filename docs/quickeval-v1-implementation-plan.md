# QuickEval V1 实施计划

> 状态：实施基线
>
> 目标：将已确认的产品、数据库、API 和前端设计拆分为可独立验收的开发迭代
>
> 更新日期：2026-07-26

## 1. 实施原则

QuickEval V1 采用模块化单体和前后端分离架构。实施按可运行的纵向功能切片推进，每个迭代结束时都应具备可演示、可测试的用户结果，不长时间只建设无法使用的底层模块。

执行规则：

- MySQL 是业务数据的唯一事实来源，Redis 只承载 Session、限流和短期幂等数据。
- 先固定 OpenAPI 契约，再并行实现 Go Handler 和 Vue 页面。
- 业务状态迁移集中在 Go Application Service，不由前端或 Repository 拼装。
- 页面按钮根据权限和 `allowed_actions` 展示，但服务端必须再次校验。
- 每个迭代同时完成必要测试，不把全部测试推迟到最后。
- V1 优先完成端到端主路径，不提前引入微服务、消息队列、对象存储和 Python Worker。
- 每个提交保持单一目的，数据库、接口和页面的破坏性变化不能混在无关提交中。

### 2.2 V1 完成条件

V1 只有在以下主路径全部可用时才视为完成：

1. 管理员创建用户、评测对象、场景、标签和评测集。
2. 管理员维护草稿用例，通过 CSV 追加导入并发布不可变版本。
3. 普通成员选择已发布版本，独立开始、暂存并完成人工评测。
4. 每条结果可以保存回答文本、多张截图、可选 1～5 分、评语、跳过原因和 Badcase。
5. 成员可以不依赖评测集登记真实业务 Badcase。
6. Badcase 可以分配负责人、更新状态、添加备注并保留完整时间线。
7. 首页和数据看板按照确认口径汇总完成评测与有效 Badcase。
8. 应用可以在 Linux 虚机通过 Nginx 和 systemd 运行，并连接已有 MySQL、Redis。

## 4. M0：工程骨架与基础设施

### 4.1 目标

建立可以在开发机和 Linux 虚机运行的最小系统，验证 Go、Vue、MySQL、Redis、Migration、配置和日志链路。

### 4.2 后端范围

建立 `apps/api`：

- Go Module、Gin Server 和优雅退出。
- `config`、`logs`、`uploads` 路径均按可执行文件所在目录解析。
- YAML 普通配置与独立密钥配置加载。
- MySQL、Redis 连接和启动健康检查。
- 显式 Migration 命令，不在 API 启动时执行 `AutoMigrate`。
- UUIDv7 生成及 UUID 字符串与 `BINARY(16)` 转换。
- 请求 ID、结构化日志、恢复中间件、CORS 同源策略和统一错误响应。
- `/health/live` 与 `/health/ready`。
- Repository 事务辅助函数和统一分页类型。

初始 DDL需要补齐：

- `000001_initial_schema.down.sql`，仅用于开发和明确的回滚场景。
- Migration 执行记录表或选定的迁移工具约定。
- 开发环境初始管理员一次性创建命令，不在正式 Migration 中写入默认密码。

### 4.3 前端范围

建立 `apps/web`：

- Vue 3、TypeScript、Vite、Element Plus、Vue Router、Pinia、Axios 和 ECharts。
- ESLint、Prettier、Vitest 和 Playwright 基础配置。
- 应用外壳、路由错误页、全局样式和设计变量。
- API Client 基础封装、请求 ID 展示和统一错误映射。
- 开发代理 `/api/v1` 与鉴权附件路径。
- 使用一个确定的 QuickEval Logo，不逐页复制视觉稿资产。

### 4.4 接口契约

- 创建 `openapi/quickeval-v1.yaml` 基础结构。
- 先定义通用响应、错误、分页、UUID、UTC 时间、认证安全方案和健康检查。
- 建立生成前端 TypeScript 类型与客户端的固定命令。
- 生成产物可重复构建，不依赖开发者本机手工修改。

### 4.5 验收标准

- 新环境能通过一条文档化命令构建前后端。
- Migration 可对空 MySQL 数据库建出 17 张业务表。
- API 在 MySQL、Redis 正常时 `ready`，任一关键依赖不可用时明确失败。
- Vue 首页占位页可以通过 Nginx 或 Vite 访问 API 健康检查。
- 错误响应和日志包含同一个 `request_id`。
- 配置、密钥、日志和上传目录不会被提交到 Git。

## 5. M1：认证、用户与基础目录

### 5.1 用户结果

- 用户可以使用本地账号登录、修改密码和退出。
- 管理员可以创建、编辑、启停用户及重置本地密码。
- 管理员可以维护评测对象、场景、用例标签和问题标签。

### 5.2 数据表

- `users`
- `user_identities`
- `evaluation_targets`
- `scenarios`
- `case_tags`
- `issue_tags`
- `audit_logs`

### 5.3 后端范围

- Cookie Session、Redis Session 存储、CSRF 和登录失败限流。
- `PasswordHasher` 与 `IdentityProvider` 边界；V1 实现 Local Identity。
- `GET /auth/session` 返回用户、权限、功能开关、上传策略和 CSRF Token。
- 用户及基础目录 CRUD、启用、停用和排序命令。
- 固定两种角色：`member`、`admin`。
- 管理员关键写操作记录审计日志。

### 5.4 前端范围

- 登录页和 Session 恢复。
- 应用外壳、权限路由守卫和用户菜单。
- 系统管理中的基础配置、用户管理和问题标签管理。
- 无权限、Session 失效、限流和字段错误反馈。

### 5.5 核心测试

- 密码哈希验证和 Session 失效。
- 登录限流与 CSRF 拒绝。
- 普通成员不能访问管理员接口。
- 最后一个可用管理员或当前管理员的危险停用规则按最终实现约束测试。
- 已被历史数据引用的基础目录只能停用，不能物理删除。
- 停用标签不出现在新建选择器，但历史关联仍可显示。

### 5.6 验收标准

- 管理员可以创建普通成员，普通成员登录后看不到系统管理入口。
- 普通成员直接访问管理员 URL 得到 403 页面，直接调用接口也返回 403。
- 退出和管理员重置密码会使目标 Redis Session 失效。
- 系统中不存在删除用户、角色管理和权限管理入口。

### 5.7 实施结果

- 已实现本地身份认证边界、Redis Cookie Session、CSRF、登录限流、修改密码和会话统一失效。
- 已实现用户、评测对象、场景、用例标签、问题标签及审计日志 API，并使用乐观锁保护管理写入。
- 已实现登录、Session 恢复、管理员导航、用户管理、基础目录、问题标签、审计日志及 403 页面。
- OpenAPI 已覆盖 M1 接口，前端类型可以正常生成。
- `scripts/m1_smoke.sh` 已在本机 MySQL、Redis 上验证认证、权限、目录写入、审计、停用标签过滤、密码重置会话失效、退出和限流。
- Go 单元及 Redis 集成测试、Vue 检查、生产构建和 Playwright 主路径测试均已通过。

## 6. M2：评测集、版本、用例与 CSV

### 6.1 用户结果

管理员可以建立评测集、维护唯一草稿、追加导入用例并发布不可变版本；所有成员可以查看和导出已发布版本。

### 6.2 数据表

- `datasets`
- `dataset_versions`
- `version_cases`
- `version_case_tags`
- M1 的目录表

### 6.3 后端范围

- 创建评测集并在同一事务中生成首个草稿。
- 草稿用例新增、编辑、删除、启停和排序。
- 从已发布版本复制新草稿，保留 `case_key` 和标签快照。
- 发布时分配连续版本号并锁定内容。
- 版本和评测集归档、恢复规则。
- CSV 模板、预览、校验、Redis 短期 Token、提交和导出。
- 草稿、用例和版本操作的乐观锁。

### 6.4 前端范围

- 评测集总览。
- 评测集详情与版本记录。
- 草稿用例编辑器。
- CSV 导入预览。
- 发布确认对话框。
- 未保存修改的路由离开保护。

### 6.5 核心测试

- 每个评测集最多一个草稿。
- 已发布版本内容不可修改。
- 发布版本号并发分配不重复。
- 复制草稿后修改不影响已发布快照。
- 期望结果为空仍可保存和发布。
- CSV 正确解析逗号、双引号、多行中文和 UTF-8 BOM。
- CSV 任一错误行阻止整体提交；预览过期或源草稿变化时拒绝提交。
- 批量排序发生锁冲突时整体回滚。

### 6.6 验收标准

- 管理员可以手工创建至少三条用例并发布 V1。
- 可以从 V1 复制草稿、修改内容并发布 V2，V1 保持不变。
- CSV 导入先预览后追加，不存在覆盖导入入口。
- 已归档版本可查看和导出，但不能开始新评测。

### 6.7 实施结果

- Go API 已实现评测集、唯一草稿、版本发布/归档、用例 CRUD/排序和不可变快照。
- CSV 支持 UTF-8 BOM、逗号、双引号及多行字段，导入采用 Redis 一次性短期 Token，并在单事务中追加。
- Vue 已实现评测集总览、版本详情、草稿编辑器、导入预览和发布确认，页面结构按 `page_refer` 高保真参考落地。
- OpenAPI 已覆盖 M2 接口并成功生成 TypeScript 类型。
- `scripts/m2_smoke.sh` 已在本机 MySQL、Redis 上验证 V1/V2 快照、唯一草稿、一次性 Token、发布不可变、CSV 导出和归档恢复。
- Playwright 已覆盖创建评测集、进入首个草稿、CSV 预览提交和发布跳转。

## 7. M3：人工评测主流程

### 7.1 用户结果

任意成员可以基于已发布版本建立自己的独立评测，逐题保存文本证据、评分或跳过原因，退出后继续并最终完成。

### 7.2 数据表

- `evaluation_runs`
- `case_results`
- M2 的评测集快照表

### 7.3 后端范围

- 创建 EvaluationRun 并预生成全部启用用例的 pending CaseResult。
- 我的评测列表、评测详情和工作台页面聚合。
- 保存已评结果和跳过结果。
- 完成、重开、作废与有限物理删除。
- 评分、完成率、跳过数量等单次评测汇总。
- 所有写操作的权限和乐观锁。

### 7.4 前端范围

- 开始评测抽屉。
- 我的评测列表。
- 三栏人工评测工作台。
- 已完成结果只读页。
- 当前题未保存修改保护。
- 完成前汇总确认和待评定位。

### 7.5 核心测试

- 同一成员可以对同一版本重复创建独立评测。
- 不同成员的评测结果相互独立且不可越权编辑。
- 已评结果至少包含回答文本；M4 完成后规则扩展为文本或截图。
- 评分只能为空或 1～5。
- 跳过必须填写原因，且不能保留评分。
- 存在 pending 结果时不能完成。
- 完成后结果只读；重开后退出正式统计；作废为终态。
- 已完成或曾产生 Badcase 的评测不能物理删除。

### 7.6 验收标准

- 成员可从评测集详情开始评测，完成后在结果页查看全部快照。
- 刷新或退出后可以继续最近保存位置。
- 可不评分完成评测，但所有用例必须已评或跳过。
- 统计明确区分已评、已评分、跳过和待评。

### 7.7 实施结果

- Go API 已实现独立评测创建、用例结果预生成、我的评测、工作台聚合、设置更新、完成、重开、作废和有限删除。
- 创建评测支持 `Idempotency-Key`，同一人员可以对同一发布版本重复发起不同评测，相同键重试返回原记录。
- 服务端已落实回答文本、1～5 分可选评分、跳过原因、乐观锁、所有权隔离和完成前待评校验。
- Vue 已实现开始评测抽屉、我的评测列表、三栏评测工作台和已完成结果只读页，并支持未保存修改保护、待评定位和评分筛选。
- OpenAPI 已覆盖 M3 接口并成功生成 TypeScript 类型。
- `scripts/m3_smoke.sh` 已在本机 MySQL、Redis 上验证幂等创建、重复独立评测、跨用户隔离、评分/跳过、完成、重开、作废和删除规则。
- Playwright 已覆盖从发布版本开始评测、保存并下一题、跳过、完成和只读结果展示。

## 8. M4：截图与评测来源 Badcase

### 8.1 用户结果

评测人员可以上传真实业务截图，并在保存单题结果时标记 Badcase；Badcase 自动带上来源评测上下文。

### 8.2 数据表

- `attachments`
- `badcases`
- `badcase_issue_tags`
- `badcase_activities`
- `case_results`

### 8.3 后端范围

- 本地文件存储接口与 `uploads/evaluations/...`、`uploads/badcases/...` 实现。
- 图片实际类型、扩展名、大小和数量校验。
- 鉴权读取、上传、删除和重排。
- 临时文件、数据库元数据、原子移动和失败补偿。
- 保存结果并标记或恢复唯一评测 Badcase 的事务。
- 评测来源 Badcase 复用 CaseResult 原始截图，不复制文件。
- `Idempotency-Key` 保存和重复请求处理。

### 8.4 前端范围

- 多图上传、进度、缩略图、预览、重排和删除。
- 标记 Badcase 表单。
- 工作台和结果页展示关联 Badcase。
- 上传失败、证据不足、数量超限和类型错误反馈。

### 8.5 核心测试

- 单张最大 10 MB，每条所属记录最多 10 张。
- PNG、JPG/JPEG、WebP 正常；伪造扩展名和 SVG 被拒绝。
- 无文本但有截图时可以保存已评。
- 删除最后一份证据时返回 `EVIDENCE_REQUIRED`。
- 同一 CaseResult 最多产生一个有效来源 Badcase。
- 幂等重试不重复创建 Badcase 或附件元数据。
- 评测创建人、管理员和其他成员的附件权限符合设计。
- 数据库失败或文件移动失败后不留下可见的半成品。

### 8.6 验收标准

- 一条评测结果可以上传多张截图并完成评测。
- 标记 Badcase 后从结果页和 Badcase 中心都能进入同一记录。
- Badcase 详情可以追溯评测集版本、用例、评测人、评分和原始证据。
- 上传目录没有通过 Nginx 直接公开。

## 9. M5：业务 Badcase 与处理闭环

### 9.1 用户结果

成员可以不依赖评测集登记真实业务 Badcase，并通过负责人、状态、标签、截图和备注完成轻量闭环。

### 9.2 数据表

- `badcases`
- `badcase_issue_tags`
- `badcase_activities`
- `attachments`
- `audit_logs`

### 9.3 后端范围

- Badcase 组合筛选、业务来源创建、内容修改和详情页面聚合。
- 负责人分配、取消分配。
- 待处理、处理中、已解决、暂不处理的显式状态命令。
- 新增备注、无效化和重新激活。
- 状态、负责人、有效性和时间线同事务更新。
- 创建人、管理员和普通成员的细粒度权限。

### 9.4 前端范围

- Badcase 列表与组合筛选。
- 登记业务 Badcase 抽屉。
- Badcase 详情、证据、负责人、处理动作和时间线。
- 无效记录只读状态和重新激活入口。
- 乐观锁冲突时保留长表单输入。

### 9.5 核心测试

- 业务 Badcase 必须属于启用场景。
- 来源和场景创建后不能通过普通编辑修改。
- 四种业务状态迁移符合状态机。
- 状态变化、无效化和重新激活必须有说明。
- 每次负责人、状态和备注变化只追加活动，不覆盖历史。
- 无效记录不能继续处理或添加定位材料。
- 创建人只能修改自己登记的原始内容，管理员可以维护全部。

### 9.6 验收标准

- 成员可以登记一个带文本和多张截图的生产 Badcase。
- 可以分配处理人、开始处理、添加备注并标记已解决。
- 完整时间线准确展示操作者、动作、时间和说明。
- 页面和 API 均不存在物理删除 Badcase 的能力。

### 9.7 实施结果

- 业务 Badcase 支持幂等登记、创建人/管理员编辑原始内容，并强制绑定启用中的场景与评测目标。
- 列表同时覆盖评测来源和业务来源，支持来源、有效性、状态、负责人、场景、目标、环境、版本、标签、发生时间及关键词组合筛选。
- 任意有效成员可维护负责人、问题标签、处理备注、补充截图和状态；原始内容及无效化权限限定为创建人或管理员。
- 状态机已落实为 `pending → processing/resolved/deferred`、`processing → resolved/deferred`、`resolved/deferred → pending`，每次迁移必须填写原因。
- 无效化与业务状态正交；无效记录保留查询和详情能力，但除创建人/管理员重新激活外全部只读。
- 评测原始截图与 Badcase 补充截图分别返回，补充截图按 `uploads/badcases/{badcase_id}/attachments` 隔离。
- `scripts/m5_smoke.sh` 已在本机 MySQL、Redis 上验证创建与备注幂等、权限、乐观锁、附件、负责人、标签、状态、无效化/重新激活、时间线和无物理删除路由。
- Playwright 已覆盖业务登记进入详情、负责人分配、处理备注以及开始处理的关键页面闭环。

## 10. M6：首页、看板、搜索与导出

### 10.1 用户结果

用户可以快速继续个人工作，按多个维度分析已完成评测和有效 Badcase，并导出明细。

### 10.2 后端范围

- 首页页面聚合。
- 数据看板聚合和版本比较。
- MySQL 基础关键词搜索。
- 评测结果、Badcase 和 Badcase 分布 CSV 流式导出。
- 统计查询的执行计划检查和必要索引验证。

### 10.3 前端范围

- 首页个人概览、继续评测、分配给我的 Badcase 和最近评测集。
- 看板筛选、指标卡、评分分布、问题标签分布、状态分布、跳过原因和版本对比。
- 顶部全局搜索。
- 图表钻取到明细列表。
- 当前筛选条件导出。

### 10.4 统计口径测试

- 平均分和评分分布只统计已完成评测中的已评分结果。
- 跳过结果不进入平均分和评测 Badcase 率分母。
- 评测 Badcase 率只统计评测来源。
- Badcase 中心统计包含评测与业务来源的全部有效记录。
- 已重开、已作废评测和无效 Badcase 不进入正式指标。
- 没有有效样本时返回空口径，不伪造 0 分趋势。
- CSV 使用 UTF-8 BOM，筛选结果与页面一致，超过 50,000 行被拒绝。

### 10.5 验收标准

- 首页数据与个人列表明细可以相互核对。
- 看板每个数字可以通过筛选后的明细解释。
- 同一评测集 V1、V2 可以按相同口径比较。
- 图表分段可跳转至对应 Badcase 或评测明细。

### 10.6 实施结果

- `GET /api/v1/pages/home` 一次返回当前用户的进行中/已完成评测、分配给我的未关闭 Badcase、继续评测、最近发布评测集和相关 Badcase 活动。
- `GET /api/v1/pages/dashboard` 支持对象、场景、评测集、版本、评测人、Agent 版本、环境、Badcase 来源/状态/标签和时间范围筛选，并实时聚合评分、Badcase、跳过原因和版本对比。
- 看板严格只使用已完成评测；平均分仅含已评分结果；评测 Badcase 率分母为已完成评测的已评用例；正式 Badcase 指标排除无效记录；空样本返回 `null`。
- 顶部全局搜索覆盖场景、评测集、用例名称/问题/期望/判定提示，以及 Badcase 标题、描述、回答、业务单号、会话 ID 和处理备注。
- 三个导出接口沿用看板筛选，返回私有 UTF-8 BOM CSV；评测结果和 Badcase 明细包含鉴权附件 URL，限制单次 50,000 行并防止表格公式注入。
- 首页、数据看板、ECharts 分布图、版本对比、图表钻取、URL 筛选恢复、全局搜索建议和导出入口均已接入 Vue SPA。
- 新增 `000002_reporting_indexes`，全局有效 Badcase 聚合命中 `(invalidated_at, status, occurred_at)`，个人最近评测命中 `(evaluator_id, status, updated_at)`。
- `scripts/m6_smoke.sh` 已在真实 MySQL、Redis 上用 V1/V2、完成/进行中评测、有效/无效 Badcase 精确核对首页、平均分、比例分母、分布、版本比较、空样本、搜索、鉴权和 CSV BOM。
- Playwright 已覆盖个人首页、看板指标与图表、全局延迟搜索和搜索结果跳转。

## 11. M7：上线加固与 Linux 部署

### 11.1 安全

- Cookie 启用 `HttpOnly`、`Secure` 和合适的 `SameSite`。
- 全部写接口验证 CSRF。
- 密码、Session、密钥、内部路径不进入响应、审计和日志。
- 上传文件进行内容嗅探，附件下载强制鉴权并使用私有缓存。
- MySQL 和 Redis 使用最小权限账号。
- 登录、上传和导出具备合理限流。

### 11.2 部署

补齐：

- `deployments/nginx/quickeval.conf`
- `deployments/systemd/quickeval.service`
- 配置模板和密钥模板
- 构建及发布脚本
- Migration 执行脚本
- 运维检查清单

部署验证：

- 程序安装到 `/opt/quickeval`。
- `uploads`、`config`、`logs` 在升级中保留。
- Go 服务只监听本机地址，Nginx 对外提供 SPA 和反向代理。
- systemd 支持启动、停止、自动重启和日志定位。
- Vue Router history 回退正确，不将 API 404 返回为前端首页。

### 11.3 备份、升级与回滚

- 上线前备份 MySQL 和 `uploads`，两者记录同一备份批次时间。
- 先执行向后兼容 Migration，再发布应用。
- Migration 失败时停止发布，不启动不兼容版本。
- 应用回滚不自动执行破坏性 Down Migration。
- 文件备份和恢复保留相对目录结构及权限。
- 定期校验附件元数据与文件是否一致，并报告孤立文件。

### 11.4 上线验收

- 全新环境安装演练通过。
- 从上一构建升级并回滚应用二进制演练通过。
- MySQL 与附件备份恢复演练通过。
- 关键权限、状态机和统计 E2E 测试通过。
- 日志可以通过 `request_id` 定位一次失败请求。
- 不依赖 Docker 即可完成生产部署。

## 12. 测试策略

### 12.1 后端

| 层级 | 重点 | 建议工具 |
| --- | --- | --- |
| 单元测试 | 状态机、评分口径、权限判断、CSV 解析、UUID 转换 | Go `testing` |
| Repository 集成测试 | 外键、唯一约束、锁版本、事务与查询索引 | 独立 MySQL 测试库 |
| HTTP 集成测试 | Session、CSRF、DTO 校验、错误码和幂等 | `httptest` + MySQL/Redis |
| 文件测试 | 类型识别、路径安全、补偿和鉴权读取 | 临时目录 |

Repository 集成测试必须使用独立数据库名，每次测试运行执行 Migration，禁止连接生产库。测试配置必须显式包含环境标识，缺失时拒绝执行清库操作。

### 12.2 前端

| 层级 | 重点 | 建议工具 |
| --- | --- | --- |
| 单元测试 | 状态文案、评分组件、错误映射、筛选序列化 | Vitest |
| 组件测试 | 表单校验、上传队列、冲突对话框、路由离开保护 | Vue Test Utils |
| E2E | 登录、发布版本、完成评测、登记和解决 Badcase | Playwright |

E2E 只保留高价值主路径，不为每个表格筛选组合编写浏览器测试。

### 12.3 必须长期保留的回归场景

1. 管理员创建成员并登录。
2. 创建评测集、导入 CSV、发布版本。
3. 两名成员基于同一版本分别完成评测。
4. 一条结果只有截图且未评分，仍可完成。
5. 一条结果跳过，不进入平均分。
6. 从评测结果标记 Badcase 并解决。
7. 直接登记业务 Badcase 并无效化、重新激活。
8. 并发修改触发乐观锁冲突且不覆盖数据。
9. 看板统计与明细数据一致。
10. 未登录用户不能读取附件。

## 13. 提交与合并建议

每个迭代按小提交推进，推荐顺序：

1. 契约或 Migration。
2. 领域规则和测试。
3. Repository 与集成测试。
4. Service、Handler 和 HTTP 测试。
5. 前端 API 类型与数据层。
6. 页面、交互和组件测试。
7. 该迭代 E2E 与文档。

不要在一个提交中同时进行大规模重命名、格式化和业务功能开发。每个迭代合并前执行：

```text
Go 格式检查
Go 单元与集成测试
Vue lint
Vue 类型检查
Vue 单元测试
前端生产构建
关键 Playwright E2E
Migration 空库验证
```

## 14. Definition of Done

任一功能只有同时满足以下条件才算完成：

- 已实现 API 和页面主路径。
- 权限、状态和输入规则在服务端生效。
- OpenAPI 与实际请求响应一致。
- 关键成功、失败、空状态和并发冲突有明确界面反馈。
- 必要单元或集成测试通过。
- 新增数据库查询经过索引或执行计划检查。
- 关键操作具有请求 ID、结构化日志和必要审计记录。
- 不提交真实密钥、上传文件、运行日志和本地环境文件。
- 相关设计或运行文档已同步更新。

## 15. 建议立即开始的任务

进入 M7“上线加固与 Linux 部署”，建议按以下顺序落地：

1. 完成安全基线复核、依赖漏洞扫描、密钥轮换和生产配置校验。
2. 在空库与历史版本数据库上验证 migration up/down、备份恢复和升级回滚。
3. 补齐关键服务集成测试、并发冲突测试和浏览器兼容回归。
4. 完成 Nginx、systemd、日志轮转、健康检查和优雅停机配置。
5. 编写 MySQL、Redis、`uploads` 的备份恢复手册并执行一次演练。
6. 使用接近生产的数据量进行看板、搜索和 CSV 导出的容量与超时验证。
